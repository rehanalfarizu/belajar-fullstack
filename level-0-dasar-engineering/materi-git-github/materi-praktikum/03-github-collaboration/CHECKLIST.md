# CHECKLIST — GitHub Collaboration

Centang dengan jujur. "Bisa" artinya bisa tanpa melihat contoh atau bertanya ke AI.

---

## Pemahaman Konsep

- [ ] Aku bisa menjelaskan beda fork dan clone
- [ ] Aku bisa menjelaskan beda `origin` dan `upstream`, dan kenapa push ke repo orang lain ditolak
- [ ] Aku paham apa itu Pull Request dan kenapa perubahan tidak langsung di-push ke `main`
- [ ] Aku paham arti base branch dan compare branch di sebuah PR
- [ ] Aku paham tujuan code review: menemukan masalah lebih awal dan berbagi pengetahuan, bukan menyalahkan

---

## Kemampuan Praktis

- [ ] Aku bisa fork (repo orang lain), clone, dan mengecek remote dengan `git remote -v`
- [ ] Aku bisa membuat branch, commit, push, lalu membuat Pull Request
- [ ] Aku bisa membaca tab Files changed dan memberi komentar di baris tertentu
- [ ] Aku bisa merge PR sebagai owner, lalu menarik hasilnya ke laptop dengan `git pull`
- [ ] Aku bisa menambahkan `upstream` dan menyinkronkan fork dengan repo asli

---

## Kebiasaan Baik

- [ ] Aku menarik perubahan terbaru `main` sebelum membuat branch baru
- [ ] Judul dan deskripsi PR-ku menjelaskan apa yang berubah dan kenapa
- [ ] Komentar review-ku spesifik (menunjuk baris dan memberi alasan), dan sopan
- [ ] Saat me-review, aku mengecek apakah ada password, token, atau file `.env` yang ikut ter-commit
- [ ] Aku tidak merge PR milik orang lain tanpa membaca isinya

Mengecek rahasia yang bocor adalah bagian dari review. Bahan lengkapnya di
[Konfigurasi Aman](../../../../modul-keamanan-web/07-konfigurasi-aman/README.md).
